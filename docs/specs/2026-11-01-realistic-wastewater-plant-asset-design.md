# ICE3 Studio 工程评审级污水处理厂资产设计

> Document ID: ICE3-STUDIO-SPEC-012
>
> Status: Implemented
>
> Owner: ICE3 Studio maintainers

## 1. 目标

将 `projects/wastewater-plant` 从低细节参数化示意图升级为一套原创、自洽、可专业
评审的通用 10 万吨/日市政污水处理厂资产。

目标不是复刻某一座真实处理厂，也不是制作影视级写实资产。资产应同时满足：

- 远景可以识别完整处理流程、功能分区和主要检修流线。
- 近景可以识别池型、管线、阀门、泵组、栏杆、平台和设备用途。
- 所有构件继续由 Studio Document 和 Component Definition 表达，保持可编辑、可回放、
  可 diff 和可增量求值。
- 不复制参考图片中的具体厂区、建筑、标识或设备布置，不把参考图片引入仓库或发布物。

## 2. 当前问题

当前工程约 12.3 万有效三角形、30 个组件定义和 191 个实例。主体比例与拓扑已经成立，
但存在以下可信度缺口：

- 传统活性污泥处理段多为一对一镜像复制，功能关系正确但缺少真实厂的交通和检修组织。
- 圆形池壁按直段盒体拼成，远景出现扇贝状轮廓；刮泥机、平台和栏杆细节不足。
- 主要管线缺乏弯头、法兰、阀门、穿墙套管、检查和支撑，部分端点看起来悬空或直接插入池壁。
- 设备多为基础方块或圆柱，无法从轮廓判断泵、鼓风机、格栅、加药和脱水设备。
- 混凝土、钢、玻璃、道路和水面主要依赖纯色区分，缺少水线、接缝、压顶和设备周边磨损。
- 大块同色草坪、等距树列和规则道路让厂区更像规划图，而不是运行中的工业场地。
- 默认视角缺少足够的信息层次，必须依赖对象树才能理解场景。

## 3. 设计范围

### 3.1 工艺基线

资产采用通用市政污水处理路线：

```text
进水
  → 粗/细格栅
  → 提升泵房
  → 曝气沉砂池
  → 初沉池
  → 厌氧 / 缺氧 / 好氧池
  → 二沉池
  → 深度过滤
  → 紫外消毒
  → 出水

污泥支线
  → 污泥浓缩
  → 厌氧消化
  → 脱水
```

两条生物处理系列共用进水、深度处理和污泥区。两条系列可以采用相同组件族，但不得做
无条件镜像；支路、设备棚、管道接驳和检修场地应产生可解释差异。

### 3.2 不在范围内

- 特定城市的真实厂区、真实设备位号或可识别建筑复刻。
- 工艺仿真、水力计算、实时控制逻辑和报警策略。
- 动画级水流、活性污泥 CFD、烟雾或天气特效。
- 外部高精度模型烘焙或依赖私有资产格式。
- 与本次资产可信度无关的 Studio API、权限或存储重构。

## 4. 视觉与工程方向

视觉目标是清朗、真实、可读的工业航拍，而不是高饱和彩色示意图。

- 混凝土使用暖灰和米灰两组基础色，并增加压顶、分缝、勒脚、水线和局部污渍。
- 镀锌栏杆、不锈钢设备、彩涂管线和金属屋面保持不同冷暖、明度和粗糙感。
- 道路使用深灰沥青，增加路缘、排水沟、检查井、装卸硬地和导向标线。
- 不同水体具有可区分的颜色和表面特征：原水偏浑、缺氧区深色、好氧区含泡沫、
  二沉池较清、污泥区呈褐黑色。
- 构筑物底部增加克制的接触暗部；不依赖当前关闭的 Engine 阴影通道。
- 植物从等距单树重复改为成组、错位、有疏密的布置，并形成厂界缓冲带。
- 重要设备使用可识别轮廓，不以单纯提高全局细分代替工程细节。

## 5. 组件体系

### 5.1 构筑物组件

核心构筑物拆为可复用组件族：

| 组件族 | 关键真实特征 |
|---|---|
| 格栅渠 | 进水渠、机械格栅、平台、栅渣收集、闸门和检修净距 |
| 提升泵房 | 泵坑、立式或潜水泵、进出水阀组、吊装空间、通风和电控区 |
| 沉砂池 | 阶梯砂斗、曝气支管、刮砂桥、集砂槽和检修通道 |
| 初沉池 | 高池壁、中心进水井、周边堰、刮泥机、半桥或全桥、楼梯和栏杆 |
| 生物池 | 多廊道、导流墙、曝气支管、跨池检修平台、泡沫区和独立阀门组 |
| 二沉池 | 高池壁、中心进水井、周边出水堰、旋转刮吸泥机、连续栏杆和楼梯 |
| 滤池 | 分格池体、滤料层、反冲洗管、操作平台和阀组 |
| 消毒渠 | 进水整流、灯架、检修平台、溢流和放空接口 |
| 浓缩池 | 中心搅拌或刮泥装置、出水堰、污泥区和独立操作平台 |
| 消化池 | 圆柱池体、分级锥顶、外壁爬梯、环形平台、安全阀和连接管廊 |
| 脱水机房 | 设备棚、离心机或压滤机、药液罐、输送设备和装卸区 |

### 5.2 通用工程组件

新增或扩充以下可复用组件：

- 管廊模块：立柱、横梁、纵梁、支墩、走道和分层管道。
- 检修模块：直梯、斜梯、跨越池体的栈桥、双栏杆和踢脚板。
- 管道模块：直管、弯头、三通、异径管、法兰、穿墙套管、阀门和检查井。
- 设备模块：泵、电机、鼓风机、格栅机、刮泥机、加药装置、换热器和小型控制柜。
- 场地模块：路缘、排水沟、井盖、硬地、厂界围栏、路灯和雨水口。

组件应通过类型化参数控制主要尺寸，并公开稳定端口。参数不得使用某个具体工程的业务
术语；行业专用含义放在实例 metadata、关系或组件元数据中。

## 6. 厂区布置

厂区按功能组织为六个区：

1. 进水与预处理区。
2. 初沉与生物处理区。
3. 二沉与深度处理区。
4. 污泥浓缩、消化和脱水区。
5. 鼓风机、加药、配电和控制等辅助生产区。
6. 入口、停车、装卸、维修和厂界缓冲区。

道路形成可连续检修的环路，池间道路兼作设备运输和消防通道。构筑物之间保持可解释的
检修净距；管线集中在管廊、管沟和图面允许的短距离接驳中通过，不穿越建筑内部或池体
核心处理区。

## 7. 管线系统

所有连接继续使用 `connection.create`，但生成和校验规则升级为：

- 管线由端口生成，终点必须落在构筑物端口、泵组或阀组上。
- 工艺水、空气、上清液和污泥使用不同路由策略：
  - 空气主管和跨区工艺主管进入管廊。
  - 原水和长距离重力流进入管沟或埋地管。
  - 同排构筑物之间允许短距离地上接驳。
- 每个地上管网至少包含弯头、法兰和支撑；阀门布置在泵出口、支管分流、池体接驳和
  管廊转换处。
- 埋地管通过检查井、局部管沟和地面标牌表达，避免在画面中完全消失。
- 构筑物增加闸门、堰板、溢流口、放空口、回流管和检修接口。
- 管线 metadata 记录 `medium`、流向、管线和设备标识；校验拒绝介质不匹配和悬空端点。

颜色编码用于辅助识别，不替代管线编号和流向标识。参考方向为：

| 介质 | 色彩方向 |
|---|---|
| 原水 / 初级工艺水 | 中性灰或低饱和蓝灰 |
| 混合液 / 回流液 | 低饱和棕金 |
| 二沉出水 / 清水 | 低饱和青绿 |
| 空气 | 工业浅蓝 |
| 污泥 | 深褐 |

## 8. 材质与表面

当前 Studio material model 只提供基础色和透明度，因此本次优化优先通过材质分组和几何
细节建立层次，不引入外部纹理依赖。

新增材质分组至少包括：

- 新混凝土、旧混凝土、池壁压顶、湿水线和污泥污渍。
- 镀锌钢、涂装钢、不锈钢、铸铁和深色格栅。
- 低反射金属屋面、浅色屋面、立面墙板和玻璃。
- 沥青、混凝土硬地、路缘、排水沟和标线。
- 草坪、绿篱、树干和两种以上叶冠。
- 五种介质管线，以及对应的阀门和设备外壳。

池壁分缝、压顶、水线、池底沉淀带、设备周边污染和路面标线使用薄几何或独立材质层
表达。不得用大面积纯黑贴片模拟阴影。

## 9. 相机与信息层

提供六个固定验收视角：

1. 全厂总览。
2. 进水与预处理。
3. 生物池与曝气系统。
4. 二沉池与回流管线。
5. 深度处理与出水。
6. 污泥处理和管廊。

对象名称使用专业、可读的中文工程名称。纯技术生成名称例如 `标线 z=-179` 应改为
“南侧道路标线”等有语义的显示名，原始稳定 ID 保持不变。

## 10. 实现结构

为避免继续扩大单体脚本，模型源码拆入一个专用目录：

```text
scripts/wastewater-plant/
  model-kit.mjs
  components.mjs
  site-plan.mjs
  validate.mjs
```

`scripts/build-wastewater-model.mjs` 保留为命令入口，并导出 `buildPlan` 兼容现有测试。

| 文件 | 职责 |
|---|---|
| `model-kit.mjs` | 参数化几何、端口、连接和通用工程组件 |
| `components.mjs` | 处理构筑物与设备组件族 |
| `site-plan.mjs` | 实例、分区、道路、景观和连接布局 |
| `validate.mjs` | 工程不变量、碰撞净距、连接完整性和预算检查 |

新增测试只放入现有 `scripts/tests/`，不创建新的测试目录。生成工程继续写入
`projects/wastewater-plant`。验收截图使用现有 `output/`，采用固定文件名，交付前删除
临时浏览器状态和不再需要的中间截图。

## 11. 数据与确定性

优化后的模型继续保持：

- 相同输入生成相同 Component Definition、节点顺序、关系顺序和内容摘要。
- 共享几何复用，不为追求细节无限复制相同 Mesh。
- 稳定端口 ID 和 semantic Node ID，不因视觉细部增加而改变业务身份。
- 组件摘要只引用内容寻址组件文件，不在 revision 中复制完整组件定义。
- 各类 ID 在全局唯一；增加细部后不得出现重复 Selection identity。

## 12. 工程校验

新增生成计划校验至少覆盖：

- 每个连接都有有效起点、终点和匹配介质。
- 每个端口最多连接一次，除非明确声明汇合或分流组件。
- 所有管线段首尾闭合，不允许悬空端点。
- 构筑物、建筑和主要道路之间不存在明显穿插。
- 管线不穿过池体核心处理区、建筑内部或另一条主管。
- 每个处理阶段至少有一个可访问的平台或检修通道。
- 所有材质引用存在，所有实例参数满足组件约束。
- 稳定摘要可重复。

校验失败必须在创建 revision 前中止，不发布部分工程。

## 13. 性能预算

目标是在增加真实细节的同时保持浏览器和 Studio 增量求值可用：

| 指标 | 目标 |
|---|---:|
| 有效三角形 | 300,000 - 500,000 |
| 唯一三角形 | 不超过 150,000 |
| 展开节点 | 不超过 15,000 |
| 组件定义 | 不超过 120 |
| 实例 | 不超过 500 |
| 材质 | 不超过 48 |
| 冷生成时间 | 目标 30 秒以内 |
| 浏览器加载 | 现有本地环境下无页面错误 |

超出上限必须说明哪个视觉目标需要额外预算，不得无条件放宽门禁。

## 14. 测试与验收

### 14.1 自动化测试

新增单元测试覆盖：

- 组件数量、端口和材质引用。
- 管线连通性、介质匹配和无悬空端点。
- 分区净距、道路连续性及主要碰撞规则。
- 固定输入摘要、稳定 ID 和实例复用。
- 三角形、节点、组件和材质预算。

测试先在现有模型上失败，再通过组件与布局改造转绿。最终运行完整
`npm run verify`。

### 14.2 Chrome 视觉验收

使用系统 Chrome 对六个固定视角截图，验收：

- 页面无脚本错误或失败资源。
- 全厂总览可识别处理线、污泥区和辅助区。
- 三个处理区近景可识别池体、设备、栈桥、管线和阀门。
- 不同水体、地面和金属具有清晰但不过度饱和的材质层次。
- 构件没有明显悬空、穿插、黑面或随视角变化的异常闪面。
- 模型可以在 Studio 中旋转、缩放和选择，且交互保持响应。

视觉验收截图只保留最终需要的一至两张，其他过程截图在交付前清理。

## 15. 实施顺序

1. 建立自动工程校验和当前失败基线。
2. 拆分现有生成源码，保持输出确定性。
3. 重做核心构筑物和通用工程组件。
4. 重排厂区、道路、检修流线与管线。
5. 补充设备、阀门、材质和场地细节。
6. 进行性能与 Chrome 视觉验收。
7. 更新工程说明和能力清单，清理临时产物。

每一步必须通过对应测试后再进入下一步。

## 16. 验收标准

设计完成时：

1. 工程为原创通用厂区，不包含参考图片或具体厂区的直接复制。
2. 全厂总览不依赖对象树即可识别主要处理阶段。
3. 近景可识别至少格栅、泵、鼓风机、刮泥机、阀门、管廊和主要构筑物。
4. 所有连接管线闭合、介质一致且具有工程支撑或埋地表达。
5. 材质、水体和场地具有清晰层次，不再呈现单色示意图效果。
6. 工程通过全部新增校验和 `npm run verify`。
7. 六个 Chrome 视角无页面错误，且性能预算内可正常交互。
8. 仓库只保留一个专用源码目录、对应测试、工程数据和必要的最终验收截图。
