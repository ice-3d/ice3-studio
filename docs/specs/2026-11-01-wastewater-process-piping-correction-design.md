# 污水处理厂工艺拓扑与工程管线校正设计

> Document ID: ICE3-STUDIO-SPEC-013
>
> Status: Approved
>
> Owner: ICE3 Studio maintainers

## 1. 摘要

当前 `projects/wastewater-plant` 已具备完整的 Document、组件实例、连接和 GLB 输出，
但仍属于工艺示意图级别。视觉近景暴露出管线折角、突然入地和悬空支路；数据检查进一步
确认缺少初沉污泥、回流活性污泥、沼气等必要工艺链路，以及二沉池分流、厌氧池曝气等
工程错误。

本设计保留 Studio 的通用数据边界，分两个阶段校正案例资产：

1. 先建立完整、可验证的工艺拓扑，修正构筑物端口、站点节点和连接关系。
2. 再升级通用管线表达，让折线路径生成连续弯头、连接配件和可验证的工程路径。

所有资产修改仍通过公开 API 或 ChangeSet 提交，由 Studio Core 执行类型校验、求值、
revision 持久化和 GLB 导出。不得直接修改派生 GLB、Viewer 场景对象或 revision 快照。

## 2. 目标

- 让二沉池具有独立的回流活性污泥和剩余污泥通道，并形成回到生化系统的闭环。
- 补全初沉池排泥链路，避免初沉池只有水侧进出的工艺错误。
- 为消化池和沼气柜建立可追踪的沼气关系，消除纯装饰设备。
- 区分厌氧、缺氧和好氧池的设备配置，不在厌氧、缺氧池中错误布置曝气器。
- 用分流井、集水井和泵站表达多池分流/汇流，不用多个连接从同一端口直接叠出。
- 把脱水后泥饼从液体圆管改为输送设备或材料搬运关系。
- 修正介质材质映射，包括化学药剂、回流污泥、初沉污泥、沼气和泥饼。
- 将当前尖锐折线扫掠升级为带弯头、配件和连续截面的管线路径。
- 增加针对工艺完整性、端口用途、路径连续性和管线碰撞的失败测试。
- 通过 Studio API 重建最新工程，并在 Chrome 中完成总览与关键近景验收。

## 3. 不属于本次范围

- 水力计算、管径选型、泵扬程计算和真实处理规模校核。
- CFD、活性污泥仿真、自动控制逻辑和运行报警策略。
- 特定真实厂区、设备厂商或可识别建筑的复刻。
- 纹理烘焙、影视级材质、动画水体和天气效果。
- WebGPU 阴影、实时全局光照等与静态资产拓扑无关的渲染研究。
- 将污水处理业务术语写入 Studio Core 的通用类型系统。

## 4. 当前缺陷与根因

### 4.1 工艺拓扑缺陷

| 缺陷 | 当前事实 | 后果 |
|---|---|---|
| 初沉池无排泥口 | 初沉池只有 `inlet` 和 `outlet` | 初沉污泥没有去向 |
| 二沉池无 RAS 回流 | 二沉池只有 `waste-sludge` 出口，并全部接往浓缩池 | 活性污泥无法回到生化系统 |
| 多池分流无节点 | 好氧池出口直接连接三座二沉池 | 多根支管从同一点叠出，缺少分流井 |
| 沼气柜孤立 | 消化池没有沼气口，沼气柜端口为空 | 沼气柜成为无功能装饰 |
| 厌氧/缺氧池错误曝气 | 三类生化池复用同一曝气池模板 | 工艺含义与设备布置冲突 |
| 泥饼按液体处理 | `dewatered-sludge` 使用圆管连接 | 设备类型和输送方式错误 |
| 介质材质不完整 | `chemical`、`dewatered-sludge` 落到默认工艺水材质 | 图面颜色与介质语义不一致 |

### 4.2 管线几何缺陷

Studio 当前把连接路径展开为折线，再沿折线扫掠圆环。路径在 90 度转角处只有一个
中心点，圆环朝向在相邻段之间急剧变化，没有真实弯头或斜接；端点只有端盖和示意法兰，
没有与墙体、套管或设备喷嘴连续的重叠几何。

埋地管进入地下后只在路径中点放置一个井盖，缺少管沟或连续地下标识。多根管线从同一
端口直接发散，无法用分流器、三通或集配水构件表达。

### 4.3 校验假阳性

当前资产校验只检查：

- 连接两端实例和端口存在。
- 端口介质字符串与连接介质一致。
- 关系 ID 存在。
- 管道配件引用已有 `lineId`。
- 组件包围圆之间没有明显重叠。

它没有检查工艺图完整性、端口用途和容量、RAS 闭环、气体链路、管线连续性、弯曲半径、
穿墙、跨池碰撞或支吊架间距。因此“校验通过”不能证明资产可工程评审。

## 5. 总体架构

```text
资产源码（P&ID、组件、站点布局、管线策略）
        │
        │  类型化 Operation
        ▼
Studio Server document.apply / ChangeSet
        │
        ▼
Studio Core 校验 + 求值 + 连续管线几何
        │
        ├── Document revision
        ├── 派生 mesh / 诊断 / bounds
        └── GLB / Viewer preview
```

资产级工艺语义位于 `scripts/wastewater-plant/`。通用连接、路径和扫掠属于 Studio Core；
Core 不识别“初沉池”“RAS”或“沼气柜”等业务词。

## 6. 阶段一：工艺拓扑校正

### 6.1 初沉污泥

初沉池新增向下的 `primary-sludge` 端口。两座初沉池分别连接初沉污泥集泥井，再由集泥井
接入浓缩或消化路线。初沉污泥连接使用埋地策略，不以地上长管跨池。

新增的集泥井必须具有：

- 两个独立入口，不允许把两条连接叠在同一端口。
- 至少一个可识别的出泥方向。
- 井盖、井筒和与地下管方向匹配的接口。

### 6.2 回流活性污泥

二沉池拆分为两个独立出口：

- `return-sludge`：回流活性污泥。
- `waste-sludge`：剩余活性污泥。

所有二沉池的回流口进入回流污泥泵站或集水井，再由泵站分别送至两条生化线。生化池增加
与 `return-sludge` 匹配的回流入口，通常落在缺氧段前端。

剩余污泥继续进入浓缩、消化和脱水路线，不得与回流污泥共用同一出口。

### 6.3 二沉池分流

每条生化线在好氧末端与三座二沉池之间增加分流井。好氧池先连接分流井入口，分流井再以
三个独立出口连接三座二沉池。分流井提供实际可见的井体、进出水方向和维护空间。

### 6.4 厌氧、缺氧和好氧构筑物

生化池组件按工艺模式区分：

- `anaerobic`：导流墙、潜水搅拌器和水面/泡沫带，不生成曝气支管和扩散器。
- `anoxic`：导流墙、潜水搅拌器和回流入口，不生成曝气支管和扩散器。
- `aerobic`：保留曝气总管、支管、扩散器、走道和栏杆。

三个阶段可以共享尺寸、池壁、导流墙和栏杆辅助函数，但不得共享错误的设备集合。

### 6.5 沼气系统

消化池新增 `biogas` 出口，沼气柜新增明确的 `gas-in` 和 `gas-out` 或对应的安全放空
接口。消化池沼气先进入集气总管，再连接沼气柜。气体管线使用独立材质和路径策略。

沼气柜如果在当前阶段没有下游利用设备，可以终止于安全放空或火炬组件；不得以无端口
球体结束。

### 6.6 泥饼输送

脱水后的泥饼不再通过圆形液体管扫掠。脱水机至泥饼仓或装车区使用可见输送机、螺旋输送
壳体或封闭料斗，Document 中使用材料搬运关系表达设备间语义。

如果当前 API 没有专用输送设备类型，则在资产组件层创建输送机几何和端口，连接介质
改为 `dewatered-cake`，但 Core 不新增业务枚举。

## 7. 阶段二：工程管线路径

### 7.1 路径模型

连接仍由起止端口、方向和路径策略生成，不引入平行管网真源。路径输出从折点列表升级
为带转弯描述的连续中心线：

- 每个转弯具有有限弯曲半径。
- 曲率由管径和可配置倍数推导，并受可用净距约束。
- 弯头区域使用圆弧采样，不把单个折点直接当作圆环位置。
- 相邻路径段共享边界环，扫掠结果保持闭合。

### 7.2 配件和端口

管线配件由资产层生成，使用同一 `lineId`：

- 端点法兰、阀门和设备喷嘴。
- 分流井、集水井、三通和异径管。
- 地上管线的支吊架。
- 埋地管线的检查井、局部管沟和地面标牌。

配件不得仅贴在端点表面；接口位置、直径和朝向必须与端口几何有明确重叠。

### 7.3 路由策略

保留现有 `direct`、`orthogonal`、`buried` 和 `rack` 策略，并为其统一增加有限弯曲
半径。资产继续按介质指定策略：

| 介质 | 策略 |
|---|---|
| 初沉污泥、剩余污泥、RAS | buried |
| 二沉出水、混合液 | buried |
| 曝气空气 | rack |
| 同排短距离工艺水 | orthogonal |
| 泥饼 | 材料输送，不使用液体管线 |

### 7.4 管线支撑

地上管线按稳定间隔生成支吊架，转折点和阀门两侧必须至少各有一个支撑。支架方向和
高度来自中心线，不从两端中点估算。

埋地管线不需要地面连续支撑，但需要在转弯、穿越道路和检修节点处提供检查井。

### 7.5 功能颜色契约

管线颜色按功能分组，不用单一色系统一覆盖。颜色是工艺阅读辅助，不替代 `medium`、
`lineId`、流向和文字标识。

| 颜色 | 功能类别 | 介质 |
|---|---|---|
| 亮银 | 普通原水与工艺水 | `raw-water`、`screened-water`、`lifted-water`、`degritted-water`、`settled-water`、`mixed-liquor` |
| 绿色 | 清水与出水 | `secondary-effluent`、`filtered-water`、`final-effluent` |
| 蓝色 | 气体 | `air`、`biogas` |
| 红色 | 污泥 | `primary-sludge`、`return-sludge`、`waste-sludge`、`thickened-sludge`、`digested-sludge` |
| 黄色 | 化学药剂 | `chemical` |

同一功能组可以按介质使用同色系的轻微明度差异，但必须保持该组主色可辨。亮银、绿色、
蓝色、红色和黄色是阶段二视觉验收的强制检查项。

## 8. 数据与 API

### 8.1 资产修改

初次重建通过现有脚本调用 Studio 公开 API：

1. `project.create`
2. `document.apply` 提交类型化 Operation
3. `validation.get` / `evaluation.stats` 检查失败关闭和预算
4. `export.sourceGlb`
5. Viewer 读取最新 revision

交互式修改使用 `changeset.create`、`changeset.add`、`changeset.evaluate`，人工批准后
`changeset.commit`。Agent 不得绕过 ChangeSet 直接改派生场景。

### 8.2 连接语义

连接继续使用 `connection.create`。以下字段保持稳定：

- 起止实例与端口。
- 介质与直径。
- 路径策略。
- `lineId`、流向和服务名称。

新增加的工艺含义通过组件端口、实例 metadata、关系类型和资产测试表达，不把污水业务
字段加入 Core 通用结构。

### 8.3 兼容性

- 现有连接 Operation 字段保持兼容。
- 第一阶段不需要破坏性 API 变更。
- 第二阶段可以改变同一路径策略的派生几何，但不得改变 Document 语义。
- GLB 是派生结果，重建后允许内容摘要变化。

## 9. 错误处理

以下情况必须在创建 revision 前失败：

- 必需工艺端口不存在或介质不匹配。
- 同一普通端口被多条连接复用，而端口未声明为集配口。
- RAS、初沉污泥、沼气或气柜链路不完整。
- 厌氧/缺氧池包含曝气扩散器。
- 泥饼使用液体圆管连接。
- 连接路径出现零长度段、非有限坐标或不合法弯曲半径。
- 管线穿过建筑实体、池体核心处理区或另一条主管。
- 管线端点与端口之间的世界坐标误差超过容差。
- 新增资产超过现有三角形、节点、实例和材质预算。

诊断必须指出失败工艺、节点、连接和端口，而不能只报告几何摘要不一致。

## 10. 测试策略

### 10.1 资产契约测试

- 两座初沉池均有独立的 `primary-sludge` 端口和埋地出泥连接。
- 每座二沉池均有 `return-sludge` 和 `waste-sludge` 两个独立出口。
- 两条生化线均存在从 RAS 泵站到缺氧段的完整回流路径。
- 好氧池到三座二沉池必须经过分流井。
- 消化池沼气经过集气节点进入沼气柜或安全放空。
- 厌氧/缺氧池不含曝气扩散器，好氧池保留曝气系统。
- 脱水泥饼链路不使用 `pipe-*` 材质。
- 每种介质都有独立且稳定的材质映射。

### 10.2 Core 几何测试

- 直角转向的中心线在弯头区域连续，相邻环共享位置且无零长度段。
- 弯曲半径小于可用线段长度；不足时产生明确诊断。
- 起点方向、终点方向和端口方向一致。
- 扫掠网格无 NaN、退化三角形或开放端盖。
- 路径几何的 bounds 包含所有弯头和端盖。

### 10.3 集成测试

- 通过 Studio API 应用完整 Operation 计划后 revision 只增加一次。
- 非法工艺图在 revision 创建前失败，原 revision 不变。
- 重新打开工程得到相同节点顺序、端口引用和路径摘要。
- 最新 GLB 可被内部预览管线加载，Viewer 无控制台错误和空白视口。
- 大场景预算与现有性能基线不退化超过约定阈值。

### 10.4 视觉验收

在 Google Chrome 固定以下视角：

1. 全厂总览。
2. 进水、初沉和生化前端。
3. 好氧池、分流井和首座二沉池。
4. 二沉池 RAS 泵站与回流主管。
5. 污泥浓缩、消化、沼气柜和脱水区。
6. 深度处理与出水。

验收要求：

- 管线在端点、转角和入地位置没有可见断口。
- 多池分流通过可识别的构筑物完成。
- 厌氧、缺氧和好氧设备轮廓不同。
- 沼气柜不再是孤立设备。
- 管线不跨越池体核心处理区。
- 截图写入现有 `output/`，临时浏览器状态不进入仓库。

## 11. 性能预算

沿用 `ICE3-STUDIO-SPEC-012` 的总预算，并优先把三角形用于真实结构和管线连续性：

- 有效三角形：300,000 至 500,000。
- 唯一三角形：不超过 150,000。
- 展开节点：不超过 15,000。
- 组件定义：不超过 120。
- 实例：不超过 500。
- 材质：不超过 48。
- 连续管线导致的求值增量不得使现有 benchmark 基线失败。

不得通过无限提高圆管径向分段来伪装细节。新增预算应先用于弯头、分流节点、混合设备和
真实端口连续性。

## 12. 交付顺序

### 阶段一

- 资产 P&ID 端口与连接校正。
- 厌氧、缺氧、好氧组件拆分。
- 分流井、RAS 泵站、初沉集泥井、沼气节点和泥饼输送组件。
- 工艺完整性校验及资产测试。
- 通过 Studio API 重建项目并完成 Chrome 验收。

### 阶段二

- Core 连续弯头路径。
- 路径转向点和配件对齐。
- 管线碰撞与支撑校验。
- Core 单元测试、集成测试和性能门禁。
- 再次重建资产并完成近景验收。

两个阶段分别提交和验证，避免工艺纠正与 Core 几何升级同时混合。

## 13. 验收标准

- 新工程通过全部现有门禁和本设计新增测试。
- 所有关键工艺链可从端口和关系图追踪。
- 不存在孤立沼气柜、无去向初沉污泥或无 RAS 回流。
- 管线近景不存在由零弯头或错误端点造成的断裂观感。
- 工程仍通过 Studio 公共 API 重建，Document 保持唯一真源。
- Viewer 可在 Chrome 中加载最新 revision，关键视角无空白、黑面或失败资源。
- 文档、资产统计、计划状态和实际实现一致。
